Set up, in order

Two sequences, because each is one. No signup: a sandbox key comes back from the first call, ready to use immediately. Every command below has its own copy control.

The ledger

Mint a key, open a ledger, move money, verify.

01

Mint a key

No signup. The secret is shown exactly once, in this response.

curl -s -X POST https://plutus-ten-eta.vercel.app/v1/keys

02

Open a ledger

Save the key as $KEY and the ledger id from this response as $LEDGER.

curl -s -X POST https://plutus-ten-eta.vercel.app/v1/ledgers \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"shop"}'

03

Move money

A world account is created lazily the first time an asset is used. This funds a till account from the world, then between accounts the same way.

curl -s -X POST https://plutus-ten-eta.vercel.app/v1/ledgers/$LEDGER/transfers \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: fund-1" \
  -d '{"legs":[{"from":"world:GHS","to":"'$TILL'","asset":"GHS","amount":"125000"}]}'

04

Verify

Recomputes the whole hash chain from the first entry and proves every asset sums to zero. A stranger can run this without ever holding a key to someone else's ledger, since a public key still only reads its own.

curl -s https://plutus-ten-eta.vercel.app/v1/ledgers/$LEDGER/verify \
  -H "Authorization: Bearer $KEY"

The exchange

Faucet, sign, place, read. Trading endpoints sign every request instead of sending a bearer token, so this half needs one more step than the ledger did.

05

Faucet

Funds the caller's sandbox exchange wallet from the world: 100,000 USDT, 1 BTC and 10 ETH, once per 24 hours per key. This call is itself signed, so it needs the signing step below before it can actually be sent; it is placed first here because it is the first thing a trading key does.

POST /v1/exchange/faucet
Content-Type: application/json
X-Plutus-Key-Id, X-Plutus-Timestamp, X-Plutus-Recv-Window, X-Plutus-Signature

06

Sign

Four headers travel with a signed request: X-Plutus-Key-Id, X-Plutus-Timestamp in Unix milliseconds, X-Plutus-Recv-Window (optional, default 5000ms), and X-Plutus-Signature, a hex HMAC SHA256 over the timestamp, the method, the path and the body, keyed by the SHA256 digest of the key secret rather than the secret itself, since that digest is all the server ever stores.

This example uses a key id and secret invented for this page, so the signature can actually be recomputed rather than taken on trust.

Key id: key_4f9a2c7e1b3d4a5f8e6c9b0a1d2e3f4a

Secret: pl_test_4f9a2c7e1b3d4a5f8e6c9b0a1d2e3f4a5b6c7d8e9f0a1b2c. This key does not exist. Signing with it authenticates against nothing, live or otherwise.

The exact bytes HMAC SHA256 signs, keyed by the SHA256 digest of that secret, one line for the timestamp, the method, the path and the body, with no trailing newline after the body:

1767225600000
POST
/v1/exchange/orders
{"market":"BTC-USDT","side":"buy","type":"limit","price":"6000000000","quantity":"100000","client_order_id":"readme-worked-example"}

07

Place

The headers computed in the step above, sent with the exact body they were computed over. client_order_id travels in the body: a placement needs it, or an Idempotency-Key header, or the server refuses it named validation_failed.

BODY='{"market":"BTC-USDT","side":"buy","type":"limit","price":"6000000000","quantity":"100000","client_order_id":"readme-worked-example"}'
curl -s -X POST https://plutus-ten-eta.vercel.app/v1/exchange/orders \
  -H "Content-Type: application/json" \
  -H "X-Plutus-Key-Id: key_4f9a2c7e1b3d4a5f8e6c9b0a1d2e3f4a" \
  -H "X-Plutus-Timestamp: 1767225600000" \
  -H "X-Plutus-Recv-Window: 5000" \
  -H "X-Plutus-Signature: ee35d7b3fbfbd93a8fcb5048280505d674ad0432435614ad056d50edbdee0832" \
  -d "$BODY"

docs/place-order.mjs in the repository reimplements this same scheme with nothing but node:crypto, and places one real order against the live host from any machine outside the repository.

08

Read

Reading is signed the same way as placing, over an empty body. This reads the order back by the id the placement returned.

curl -s https://plutus-ten-eta.vercel.app/v1/exchange/orders/$ORDER \
  -H "X-Plutus-Key-Id: $KEY_ID" \
  -H "X-Plutus-Timestamp: $TIMESTAMP" \
  -H "X-Plutus-Signature: $SIGNATURE"
